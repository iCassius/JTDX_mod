# JTDX P031 用户版更新说明

版本：2.2.159.031

P031 主要修复 AutoSeq 对同一 DX 呼号反复重试、CAT 断开时恢复提示去向不一致的问题。Web/TCP 功能没有用户行为变化。

## 你会看到的变化

### AutoSeq 会遵守最大应答次数

此前，AutoSeq 在处理不同方向的解码时可能没有持续累计同一 DX 的应答次数，导致达到设置的最大次数后仍继续重试，DX 呼号也可能一直留在当前目标上。

现在，应答次数会持续累计。达到你设置的上限后，AutoSeq 会结束该目标并释放 DX，不再按旧目标继续重试。此次修复没有增加新的自动发射动作。

### 失败目标会短暂冷却，对方的真实回应仍可继续

自动选择的特殊 DX 呼号达到失败上限后，会进入约五分钟的临时冷却，避免普通 CQ 解码让同一个无进展目标马上重新占住 DX。

冷却只影响这类自动候选，不是永久屏蔽或黑名单。对方明确呼叫本台，或已经开始的 QSO 返回有效回应，仍可继续进入通联流程。冷却只保存在当前程序运行期间，重启 JTDX 后会清除。

### CAT 断开时，设置窗口不会改变运行电台的恢复去向

如果正在使用的电台 CAT 连接断开，无论 Configuration 设置窗口开着还是关着，主窗口都会继续走原有的运行连接恢复流程。单独进行的 CAT 配置测试失败仍只在设置窗口提示，不会被误当成运行电台断开。

### Web/TCP 没有用户行为变化

P031 没有改变 Web UI、TCP 监听或 UDP 的生产行为，也没有改变现有端口设置方式。

## 升级后可以这样检查

1. 启动 P031，确认应用版本显示为 2.2.159.031。
2. 在适合且安全的电台环境中，按平时的方式观察 AutoSeq 回答 CQ：尝试次数达到已设置上限后，当前 DX 是否被释放，AutoSeq 是否停止对该旧目标继续重试。
3. 观察一个达到失败上限的自动特殊目标：普通 CQ 是否暂时不再立即选中它；同时确认明确呼叫本台和已经开始的 QSO 有效回应仍可继续处理。
4. 按你的安全测试方式观察 CAT 连接中断：Configuration 窗口开关不应改变运行电台的恢复流程；独立的 CAT 配置测试错误应留在设置窗口。
5. Web UI 和 TCP 可按现有用法继续使用，本版没有相关行为变更。

## 已知边界

五分钟冷却只针对本次程序运行中的特定自动候选；退出并重新启动 JTDX 后会清除。实际设备上的 CAT 恢复和无线电行为仍取决于设备与连接环境。

P031 尚未经过真实电台 HIL 验收。本说明和自动化测试不能代替用户在自己设备上的安全验收。
