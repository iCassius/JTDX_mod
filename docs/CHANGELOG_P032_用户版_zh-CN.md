# JTDX P032 用户版更新说明

版本：2.2.159.032
Windows PE 数字版本：2.2.159.32

P032 为 AutoSeq 初次自动起呼增加可关联的本地诊断日志，并在严格的安全条件下结束长时间没有实际 TX 进展的初始 CQ/RFIN 目标。普通用户还可使用本地故障反馈导出工具，生成经时间筛选的 ZIP 供检查和反馈。

## AutoSeq 初次自动起呼停滞处理

当 AutoSeq 新选择一个自动 `RCQ` 或 `RFIN` 目标后，程序从目标选择时刻开始计时。只有在线电台 PTT-on 回读或音频输出启动确认/进度才算实际进展；重复解码、Enable Tx 切换和发送消息槽变化不会重置计时。完整实时解码批次结束时，如果连续 120 秒没有实际进展，程序才评估是否可以结束这个初始目标。

结束前会确认当前目标仍是同一呼号、模式和波段，QSO 仍在初始阶段，电台在线，PTT-off 状态已知且是本次目标选择之后收到的回读，并且没有发射、Tune、待处理 TX/PTT 请求或恢复流程。任何一项状态未知或不满足时，程序会记录阻塞原因并保留 DX。有效的本台定向呼叫或已进入有效 QSO 阶段的同批回应优先，不会因这项初次起呼计时而被清理。

这项处理只针对 AutoSeq 实际选中的新自动 `RCQ/RFIN` 初始目标，不接管手动 DX、恢复中的 QSO 或 Hound/WSPR 流程。通过安全门后，程序结束该 owner、关闭 Enable Tx 并清除 DX；同一解码批次不会马上重新选回刚释放的候选。现有普通重试与已经进入的 QSO 结束流程保持原有语义，没有新增自动发射动作。

## 本地诊断日志和故障反馈 ZIP

AutoSeq 与 CAT 会话事件写入 JTDX 数据目录中的 `jtdx_recovery.log`，同时记录本地/UTC 时间、会话与 attempt ID、当前流程状态和必要的 PTT 回读信息。活动日志最多 2 MiB，并保留 3 个同样受限的轮转文件。日志失败不会改变 CAT、AutoSeq 或 TX 流程。

在 Windows 上双击 `export-jtdx-diagnostics.cmd`，输入故障发生的本地时间（回车表示现在），工具默认导出事件前 30 分钟到后 10 分钟的日志行和有限的 AutoSeq 设置摘要，并把 ZIP 保存到桌面。导出工具只读本地文件，不启动 JTDX、不连接电台，也不会自动上传。分享前请检查 ZIP 内的 `report.txt` 和筛选日志，再自行附上相关截图；工具不收集截图。详细用法与限制见[故障反馈导出指南](autoseq/P032_故障反馈导出指南_zh-CN.md)。

导出的 INI 摘要反映导出时保存的配置，不能证明故障发生时的设置。来源文件缺失、读取失败、无效时间戳或截断都会写入报告；用户应先检查后再决定是否分享。

## 版本与验收边界

关于窗口及 Web UI 服务版本显示为 `2.2.159.032`；Windows PE 数字版本为 `2.2.159.32`。此次 Web UI 版本夹具同步更新，TCP 与 UDP 生产行为没有改变。

本机 Release 构建和自动化测试不等于真实 GUI、声卡、电台 CAT/PTT/TX 或 HIL 验收。现场曾报告过一次“Tx1 后没有后续 TX”的现象，但本轮没有在真实设备上重现，不能把自动化结果说成现场根因已被证实。请勿仅凭诊断日志或构建测试结果判断无线电实际行为。
