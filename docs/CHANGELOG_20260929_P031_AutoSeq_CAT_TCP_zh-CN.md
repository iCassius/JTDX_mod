# P031 用户可见变更：AutoSeq、CAT 恢复与端口冲突测试

## 版本

- 应用显示版本：`2.2.159.031`
- Windows PE 数字版本：`2.2.159.31`（资源版本字段会省略补零）
- 发布代号：`P031`

## AutoSeq 回答 CQ 与 DX 占用

回答 CQ 时，方向筛选现在只影响候选是否入选，不会把已积累的尝试次数重置。启用了最大回答次数后，达到上限一定会走终止清理，避免 DX 一直停留在没有进展的目标上。

自动选择的特殊目标达到上限后进入五分钟进程内冷却，持续发送普通 `RCQ/RFIN` CQ 的同一台不会在清理后立刻重新占住 DX。冷却只作用于普通 CQ 候选；向本台发送的 `RCALL/RREPORT/RRREPORT` 以及已经进入的 `RRR/RRR73` 等真实通联回应仍可继续。没有报告或报告无法解析时按最弱报告 `-60` 比较，避免坏字段被误读成较强报告。该冷却不写入配置或持久黑名单。

DX 清理仍遵循已有 PTT 安全条件：CAT 恢复路径只有在电台在线且确认 PTT 关闭后才释放旧 DX，再等待新解码。修复没有增加自动发射动作或独立的无进展定时器。

## CAT 故障去向

- 运行中的 rig 发生故障时，无论 Configuration 设置窗口是否打开，故障都进入 MainWindow 原有的 CAT/AutoSeq 恢复处理。
- Test CAT 或新建测试用 Test PTT 会话的故障只在设置页提示，不被误当成运行电台掉线。
- Test PTT 若复用了当前运行 rig，故障继续按运行会话处理。
- 接受候选 CAT 配置后才将候选会话提升为运行会话；取消时恢复/保留的旧 rig 仍属运行会话。
- 每次实际创建 rig 都有 generation。旧设备线程排队迟到的错误不会关闭新 rig，也不会触发错误的自动恢复。

原有的 PTT-on 保护、PTT-off 回读门、重连次数和恢复票据判断保持不变；没有增加发射、改变 CAT 配置迁移或引入新用户设置。

## TCP 与 UDP

Web Server 的生产 TCP/UDP 代码没有修改。自动端口冲突测试现在在 `AnyIPv4` 地址预先占用首个候选端口，并确认测试服务跳过该端口和数字 UDP 保留端口；这项变化只提高冲突测试与生产监听地址的一致性。

## 建议的用户验收重点

1. 在隔离配置或安全的接收环境下观察 AutoSeq 回答 CQ 时尝试次数持续累加；达到已设置上限后确认 DX 被释放，冷却期间相同普通 CQ 不会马上重新入选。
2. 确认短期冷却不会阻止明确呼叫本台的消息及已经开始的有效 QSO 回应。
3. 自然发生 CAT 故障时，观察 `generation`、`session_purpose` 和 MainWindow 恢复日志；分别检查配置窗口开/关、Test CAT 失败以及 Test PTT 复用运行 rig 的去向。
4. 不以自动化测试通过代替实际设备回读。实际 CAT/PTT/TX、无线电行为和长时间运行仍由用户在其设备环境中单独验收。
