# JTDX 2.2.159.066 用户版更新说明

- 应用显示版本：2.2.159.066
- Windows PE 数字版本：2.2.159.66
- 对应软件包：Windows x64 发行 ZIP；未签名；硬件在环（HIL）未验证。

本说明描述 P066 发行包中的用户可见变更与软件验证边界。P032–P035 的历史说明仍保留在源码库和软件包中；它们记录各自阶段，不是 P066 新增改动。

## P066 本次变更

- 当 `autoCallRareTargets` 启用且自动目标命中已配置优先级时，该目标达到尝试阈值后的待机清理按程序内部收尾处理，不再留下错误的 operator hold；同一解码批次避免重复收尾，后续批次可按现有规则重新选择合格目标。该修复仅限此配置的自动目标路径，不代表所有 AutoSeq CQ retry threshold 都有相同处理；收尾不会自动恢复旧 TX。详细行为与回归入口见[阈值收尾与重新起呼说明](autoseq/AutoSeq_阈值收尾与重新起呼修复_zh-CN.md)。
- 保留 P0 TX→RX 停止路径和 `m_tx_when_ready` 待发状态清理。相关隔离 MainWindow 集成用例覆盖软件控制流，不证明真实电台收到 PTT 或 RF 发射。

## 随包保留的历史功能与已知回归

- P032 加入 AutoSeq/CAT 本地诊断日志，并在满足新鲜 decode、目标 context、在线状态、目标选择后的 PTT-off 回读及无 pending/recovery 等安全条件时，清理连续 120 秒没有实际 TX 进展的初始自动 RCQ/RFIN 目标；另提供只读的故障反馈 ZIP 导出工具，不会自动上传。见 [P032 更新说明](CHANGELOG_P032_用户版_zh-CN.md)。
- P033 加入 CAT 会话代次传播、FTX-1+CAT 的成功 `GET_PTT` 就绪门、未消费请求的上下文取消保护和协议错序计数修复。软件回归不替代硬件读回。见 [P033 更新说明](CHANGELOG_P033_用户版_zh-CN.md)。
- P034 曾包含 retired worker、待发 payload 身份及 CAT 状态观察等保护；实际长挂机时发现严重回归，已撤回 P034 长挂机验收建议。不要使用 P034 包进行长挂机验收。见 [P034 更新说明](CHANGELOG_P034_用户版_zh-CN.md)。
- P035 修正 Qt queued SET 中 `PttAdmissionBlock::Token` 的生产类型注册，并补齐 Hamlib 成功 PTT GET 的 health 成功事件。软件覆盖不能证明用户报告的 15 秒恢复已在现场恢复，也不能确定 COM long-idle 根因。见 [P035 更新说明](CHANGELOG_P035_用户版_zh-CN.md)。

V066 的冻结源码快照包含 1,332 项，fingerprint 为 `597b2b192f4b0b12bff365480629abb5ae911e840297068296ff881038f361c4`。全新 Release configure、完整构建和安装均成功；未筛选的全量 CTest 为 53/53 通过，其中包含对 `autoCallRareTargets` 启用且命中已配置优先级的自动目标阈值待机清理、同批次防重复收尾与后续批次重新选取的隔离 MainWindow/Qt 事件循环用例。静态运行库审计未发现缺失 PE 依赖；隔离进程加载检查覆盖 42/42 个 DLL/Qt plugin。原 V066 stage、ZIP 和清洁解压的 157 项逐路径、大小及 SHA-256 对照一致。

P066 发行 ZIP 是在已验证的 V066 文件集上更新随包文档后重新打包；二进制未重新构建。53/53 软件测试和原 157 项包校验结果继承自原 V066 构建证据，没有因文档 overlay 重跑。发行 ZIP 自身的文件完整性校验单独记录，不构成新的构建或软件测试证据。

部分集成用例通过应用时钟偏移加速 TX 槽，RX 边界只观察约 14.9 秒；没有完整自然时钟的长时间挂机测试。没有启动正式 JTDX GUI 或正式 decoder，没有连接真实 CAT、PTT、COM、音频设备或电台，没有发射 RF，也没有执行 HIL。Hamlib `RIG_OK` 加协议检查、软件 PTT 状态和隔离加载结果都不是电台线路往返或实际 TX 的证明。

许可检查没有找到 FFTW 组件专属许可通知；随包 GPL 文本是通用文本，不替代 FFTW 专属通知。该项法律合规状态未验证。

V066 二进制基于 `main@50334d31e3f65936e1936c052078e0151780a1c8`，输入为含未提交修改的冻结工作树快照，不是该 HEAD commit 的干净构建。运行包内 49 个 PE 文件（包括 `bin/jtdx.exe`）均未做 Authenticode 签名；基线 Git commit 未签名；发行 ZIP 未附 detached `.sig`/`.asc` 签名。
